# Bro 实施方案

状态：已进入实现，形成 0.1 开发版和本机 macOS arm64 应用包；以下记录已验证部分和缺口，首版整体尚未验收完成。更新：2026-09-30。

## 目标与方案引用

依据 [项目方案](solution.md) 实现首版 bro：macOS 与 Windows 桌面工作台、单一 bro 的多会话工作、飞书与通用 Monitor、跨会话交办、Computer Use、Mnemopi，以及可切换的 Skill/上下文实验。GUI 保留 Codex 式布局，视觉按 2026-09-30 用户要求改为沙漠、仙人掌、落日、牛仔组成的像素西部工作站。

以方案中的“功能对照后的取舍”和“验收与测试策略”为需求依据。本文件规定实施顺序、改动区域、依赖和验证方法，不重新扩大功能范围；当前实现进度见下表。

仓库现已包含桌面、宿主、OMP 适配、集成、实验和测试代码。依赖固定为 OMP 18.4.3、Bun 1.4.2、Electron 44.4.5；前期源码研究提交 `d1932a6ff85613dde1160b87a73ddcdc3beb01f6` 用于接口参考，不宣称发布包与该提交逐字相同。

## 全局约束

- 产品只有一个 bro；不同任务使用不同会话，临时子代理属于内部执行能力。
- 架构沿用 Electron GUI、独立 Bun 后台宿主、按需启动的独立 OMP 会话进程。关闭 GUI 后宿主、Monitor 与任务继续运行；不把宿主生命周期绑定到 Electron 窗口。
- 宿主是队列、入口绑定、请求关联和运行状态的持久化归属；OMP 是聊天历史与会话产物的归属，Mnemopi 管理自身记忆。宿主只索引历史，不维护第二套权威对话记录。bro 使用独立的数据根目录，不默认改动已有 pi/OMP/Codex 配置。
- GUI 明确提供 queue、steer、stop；非 GUI 输入统一排队。GUI 状态更新与控制接口不需要排队等待模型。跨会话结果需要模型处理时，同样排入来源会话。
- 只有受信任的人可以使用，默认仅本人，名单内同等完整能力。身份与群聊实际 @ 在创建会话和调用模型之前检查；正文不能改变来源身份和路由。
- 首版直接使用本机账号权限，沿用 OMP 默认 `yolo`，不增设 bro 逐工具审批。系统权限和已有显式 `prompt`/`deny` 规则仍生效，必要确认按底座机制呈现，不新增审批模式选择界面。
- 双平台从第一个可运行切片开始验证。桌面进程运行于当前用户的交互式环境；合盖执行以系统实际保持运行为条件。Mac 锁屏 Computer Use 仅作非阻塞探索。
- 默认工作目录、单目录项目、绑定复用及归档/删除解绑按方案执行；不设计运行中删除/归档的特殊处理。
- 记忆开关与实验开关独立。正常功能不依赖 Jev 凭据或 Laya 安装；关闭实验要恢复 bro 选定的 OMP 常规基线。
- Plan/Goal 模式和明确不要的附加入口不实现；Appshots、微信、执行沙箱、定时任务、侧聊、复杂预览、内置共享浏览器、高级 diff、多文件夹项目及方案列出的 OMP 附加模块继续暂缓。不能只隐藏按钮却让这些模式、命令或自动发现路径默认生效。

拟按下列区域组织实现，保持 OMP 适配集中，避免复制其整个执行循环：

| 区域 | 主要内容 |
| --- | --- |
| `apps/desktop/` | Electron 主进程、preload、界面；项目/会话、输入与结果、设置与状态 |
| `apps/host/` | Bun 宿主；会话进程、持久队列、路由、请求关联、共享资源协调 |
| `packages/contracts/` | GUI—宿主—运行进程的命令、事件与来源元数据；版本与错误类型 |
| `packages/runtime-omp/` | OMP SDK、模型认证、工具/资源、历史、记忆及扩展接口的适配 |
| `packages/integrations/` | Monitor 来源适配器：飞书、Peer/SSE、进程输出、文件变化及回复转换 |
| `packages/platform/` | 用户态后台启动、系统权限、用户输入检测与桌面协调所需平台接口 |
| `packages/experiments/` | Skill 选择、上下文选择、压缩策略与 Jev/Laya 适配、比较记录 |
| `packaging/`、`tests/` | 双平台打包、兼容性探针、跨进程集成与真实端到端验证 |

## 实现步骤

### 01. 验证固定 OMP 版本与双平台运行路径

- **预期结果**：在两端用独立 Bun 进程创建、执行、关闭并恢复一个文件化 OMP 会话；最小 Electron 包能够启动该进程并取得真实工具结果。确认 SDK 导出、资源路径、桌面 worker 和原生模块可以随包运行。以小探针核实动态 Skill 选择、压缩钩子退出、记忆作用域及真人输入检测的可行接入位置，记录原生支持与需要补充的薄层，不在此步实现完整功能。
- **改动区域**：依赖清单与锁文件、`packages/runtime-omp/`、`packages/platform/`、最小 `apps/desktop/` 启动入口、`packaging/`、`tests/compatibility/`。记录源码提交与所用发布包的对应关系；若需要上游改动，集中保存差异。
- **依赖**：macOS、具有真实交互桌面的 Windows 环境及最小模型测试凭据；取得版本匹配的 OMP 包/源码与原生依赖。根仓库的 Bun 要求和子包最低版本不同，必须实际选定同一兼容版本。首次运行所需模型授权和系统权限在测试时完成。
- **验证方法**：两端分别执行“创建会话→真实工具调用→保存→退出→恢复”；检测原生截图/控件能力，确认 worker 能从打包位置加载。每项探针记录版本、调用入口、输出与缺口；静态接口存在或模拟结果不算运行通过。基础运行失败阻塞步骤 02；其他探针的未解决问题只阻塞对应能力，不能被标记为已支持。仅有明确不兼容证据时才评估 pi 备选。

### 02. 在 GUI 中完成首次登录和真实开发任务

- **预期结果**：用户打开 bro，在 GUI 完成 ChatGPT 登录或 API Key + Base URL 配置，选定模型后发起会话，完成文件编辑和测试，看到流式回复与工具结果。桌面采用项目/会话侧栏、中央对话、底部输入及按需辅助面板；从本步开始使用 Codex 参考风格。
- **改动区域**：`apps/desktop/` 的基础布局、模型设置与消息呈现；`apps/host/` 的启动与单会话调用；`packages/contracts/` 的首批命令/事件；`packages/runtime-omp/` 的认证、模型与工具事件适配。账号/API 凭据统一保存并协调刷新写入，运行进程取得所选连接；不各自维护相互覆盖的账号状态。
- **依赖**：步骤 01 的基础运行与打包路径。GUI 通过受认证的本机接口连接宿主，运行进程通过独立控制通道交互；区分协议数据与工具日志，附件传引用，避免大文件挤占控制通道。Electron 渲染层通过 preload 获取所需能力。
- **验证方法**：两端分别从 GUI 走通两种认证路径，验证流式对话、一次真实工具调用及支持图片输入的模型；覆盖登录失效、退出、错误 Key/地址/协议、手填模型 ID、重启后的配置恢复。核对实际请求地址与身份，不能静默切换计费路径。模型、推理强度、上下文与费用按真实返回展示，未知费用显示不可用或估算。

### 03. 让多会话、排队和后台生命周期可靠工作

- **预期结果**：多条会话可分别执行；GUI 可排队、steer、停止并重开恢复状态。新建/搜索/恢复/分支/重命名/置顶/归档/删除可用，一个项目对应一个目录，普通聊天使用默认工作目录。独立宿主按需启动会话进程，GUI 关闭不会结束任务。
- **改动区域**：`apps/host/` 的会话索引、进程管理、SQLite 队列与投递记录；`packages/contracts/` 的输入 ID、会话/运行 ID、接收序号、事件游标和控制确认；`packages/runtime-omp/` 的历史读取、恢复、分支及终止映射；GUI 会话列表与 queue/steer/stop。宿主是队列唯一写入者，输入与实际 OMP 执行关联。
- **依赖**：步骤 02。先固定宿主持久接收、运行进程接收、开始执行、结果持久化的确认边界；OMP 内存中的 follow-up 队列不能代替持久队列。GUI 重连以快照和后续事件恢复，不重复提交消息。
- **验证方法**：两条会话并行执行并验证模型、目录、输出不串线；忙碌时 queue 等待，steer 在可处理位置生效，stop 不被队列阻塞。关闭 GUI、重连、分别重启宿主/运行进程，验证待处理输入与历史映射；在投递/确认间中断也不盲目重复有副作用的执行。仍有后台工具/子代理的进程不回收；测量空闲恢复、启动时间和内存，再确定回收阈值。归档/删除只在本轮约定的正常使用场景验证。

### 04. 完成日常开发、产物展示与对话批注

- **预期结果**：GUI 中可以完成搜索、改代码、终端命令、测试、基础 diff、Git/worktree 与代码审查任务；保留内部临时子代理和后台工具。显示文本、图片、文件链接与工具结果；用户可选取一段或多段回复文字批注，再通过 queue 或 steer 提交。
- **改动区域**：GUI 的开发结果/终端与基础 diff 区域、附件和批注输入；`packages/runtime-omp/` 的工具事件、产物链接和开发工具配置；宿主对同一项目共享写入资源的协调。批注保存原会话/消息 ID、原文片段与意见，不凭显示文本反查目标。
- **依赖**：步骤 03；基础文件与测试路径沿用步骤 02。Hashline/AST、LSP、DAP、持久 Python/JS 直接使用底座能力，项目所需语言服务器/调试器按实际依赖检测，不扩成 IDE 界面。
- **验证方法**：用一个实际项目完成“定位问题→修改→跑测试→查看 diff”，分别验证 LSP、DAP 和持久执行环境的代表任务；验证普通安全代码审查、网页检索、图片与文档处理可用。相同文件的并发修改不能静默互相覆盖。批注覆盖多段、重复原文、旧消息、历史分支与两种投递方式；批注保存本身不触发任务。文件/终端路径覆盖中文和空格。Git/PR 工具遵循用户指令，不自动合并。

### 05. 从 GUI 管理 Skills、MCP 与插件

- **预期结果**：用户可从本地或 Git 安装资源，在 GUI 查看来源、作用域与实际生效状态，启停、更新、卸载；会话中的工具/Skill 与显示一致。保留 bro 项目规则、正常 Skill 发现和显式调用。
- **改动区域**：GUI 资源设置；`packages/runtime-omp/` 的资源发现、安装/更新与 reload 适配；宿主的资源配置写入协调和运行进程刷新通知。按需重载或在安全的会话边界重建运行进程，保留原 OMP 历史。
- **依赖**：步骤 03，复用 OMP 已有安装与配置路径；步骤 04 提供工具与产物的统一展示。已有配置刷新不等于所有扩展模块即时生效，界面需显示待生效情况。
- **验证方法**：分别安装、调用、禁用、更新、卸载一个 Skill、一个 MCP 服务和一个扩展插件，验证正在运行/重开的会话实际加载版本。核对项目/全局来源及覆盖关系、显式 Skill 调用；安装或刷新后不自动激活已暂缓的模式和附加模块。不以安装成功代替资源能被真实调用。

### 06. 用通用 Monitor 接入飞书和本机事件

- **预期结果**：关闭 GUI 后仍可通过飞书私聊或群内 @ 使用 bro。可信名单初始仅本人；私聊按入口绑定，群聊按连接/Bot、群、成员绑定。无有效绑定时新建，之后复用，归档/删除解绑。Peer/SSE、进程输出和文件变化也可作为已配置来源进入相同队列。
- **改动区域**：`packages/integrations/` 的来源适配、平台认证、正文/引用/附件与回复转换；`apps/host/` 的 Monitor、可信检查、去重、绑定事务与持久回复记录；GUI 连接、可信名单、订阅、当前绑定和健康状态。飞书优先使用官方长连接/事件接口，Monitor 管理其生命周期；不依赖抓取飞书桌面界面。
- **依赖**：步骤 03 的队列与会话接口，以及已配置的飞书应用、事件订阅、消息/附件和所需历史读取权限。接入现有 Peer 前核对真实协议、认证与回复关联；复用包装适配，不修改现有 Peer 服务。所有来源保留连接、实际发送者、事件标识、引用和回复目标等元数据。
- **验证方法**：实测本人私聊、同群不同可信成员 @、同一成员不同群、仅引用/回复 Bot、无 @ 与非可信者；后三类不唤醒模型或回复。并发首次消息只创建一条绑定；重启保留绑定、去重及队列，归档/删除后下一次有效消息新建。群上下文只带本次 @、引用及该成员历史，按需查群记录并如实报告缺失。验证真实图片/文件收发、长回复、回复失败重试与原群/私聊关联；无事件时模型调用数不增长。各本机来源完成“真实事件→会话→结果”验证，区分连接在线与自动投递开启，不恢复定时任务。

### 07. 从入口会话查询和交办其他会话

- **预期结果**：飞书绑定的 S0 可以查询 S1/S2 的状态或相关记录，也能向目标会话排队交办。宿主持久接收后先确认交办，S0 保持可聊天；目标结束后结果排回 S0，再通知原请求来源。GUI 同步展示关联与真实状态。
- **改动区域**：`apps/host/` 的会话查询、跨会话投递、目标运行控制和结果关联；`packages/runtime-omp/` 的对应工具；GUI 的来源与关联展示。保存原始请求者、入口消息、来源/目标会话及请求 ID；把任务结果和普通入站请求区分开，不把结果再次变成新的交办请求。
- **依赖**：步骤 03 与 06；跨会话输入继续使用既有队列和可信元数据。查询只返回实际所需片段，不复制整段历史；原始请求记录决定回包位置，不依赖最新活跃会话。
- **验证方法**：飞书同时交办 S1、S2，交办期间继续与 S0 聊天，按不同完成顺序核对回包；S0 或目标忙碌时结果不插队。要求停止目标任务的 IM 消息先在 S0 排队，出队后才可调用目标控制接口，不在接收阶段立即停止。覆盖失败、取消、需要补充信息、运行进程重启、发送确认中断及回复重试；实际执行状态不明时不盲目重跑。目标会话自己的 IM 入口不能误收 S0 请求的输出；有凭据的 Peer 伪造关联或引用内容也不能冒充另一请求。

### 08. 完成双平台 Computer Use 与用户接管

- **预期结果**：bro 能使用 OMP 浏览器、无障碍控件、后台窗口输入及必要的前台键鼠完成操作并读取结果；GUI 显示能力、权限、当前占用、等待和暂停。真实用户键鼠输入自动暂停共享桌面操作，只有 GUI 手动继续后恢复，独立后台任务继续。
- **改动区域**：`packages/runtime-omp/` 的 browser/computer 接入；`packages/platform/` 的两端输入检测和权限状态；`apps/host/` 的全局桌面占用及暂停状态；GUI 状态与暂停/继续。占用覆盖连贯操作，接入 worker 内部/批量动作的取消与输入前检查，不能只锁外层一次工具调用。浏览器标签页和后台窗口也按实际共享目标协调。
- **依赖**：步骤 01 的原生模块/输入检测探针、步骤 03 的多会话与运行控制。已有登录态通过 OMP 支持的浏览器连接方式使用；会自动激活窗口或不支持后台输入的操作再使用前台路径。不能将 OMP takeover、单 worker busy 或失焦检查当作 bro 的真人接管实现。
- **验证方法**：两端分别在浏览器和原生应用执行读取、截图、输入及状态核对，覆盖已登录页面、AX/后台输入和前台回退。两会话争用桌面时不得在一段输入中互换控制；真人接管后两者都停止新的桌面动作，bro 自己的输入不误触发暂停。验证长批次取消、失效引用、焦点变化、worker 崩溃与占用释放；手动继续前重新读状态。记录在途动作和实际暂停响应，不承诺撤销已发出的操作。锁屏探索记录能力与缺失，不阻塞该步骤常规桌面验收。

### 09. 操作真实 Codex 桌面端会话并回报

- **预期结果**：从 bro GUI 或飞书交办后，bro 在指定 Codex 桌面会话中定位、发送/排队并读取对应回复，沿原请求回报。此过程使用跨会话交办的异步反馈方式，等待时释放桌面占用。
- **改动区域**：`packages/integrations/` 的 Codex 桌面应用适配与结果关联，复用步骤 07 的任务记录、步骤 08 的桌面控制与 GUI 状态。优先核实能否通过受支持接口操作桌面同一会话；不成立就使用 Computer Use，不把接通 App Server 设为必需条件。
- **依赖**：步骤 07、08，以及待测系统上的 Codex 桌面应用和明确的测试会话。接口能力只有在同一桌面会话中验证通过才采用；直接读取/修改 Codex 本地状态文件不作为收发路径。
- **验证方法**：两端分别从 GUI 和飞书交办真实对话，核对目标会话、提交内容、队列状态及对应回复；目标忙碌时保持 queue 意图，不改成 steer/stop。覆盖同名目标、用户接管、等待期间其他桌面任务、多个在途请求及提交结果不明；先核对已发送记录再决定重试。模型 API 对话成功或点击发送成功均不能代替完整验证。

### 10. 接入 Mnemopi 和持久 on/off 开关

- **预期结果**：Mnemopi 首次使用默认关闭，手动选择持久保存，重启不重置。开启时按原有机制自动保留、文本检索、注入和整理；首版设置 `mnemopi.noEmbeddings: true`，默认向量模型下载与语义检索暂缓。关闭后停止模块读写及后续注入，已有数据保留，普通历史和压缩继续工作。GUI 显示开关、实际生效状态及后端支持的管理操作，重开可继续使用旧记忆。
- **改动区域**：`packages/runtime-omp/` 的后端配置/生命周期与作用域适配；宿主的设置传播和共享存储协调；GUI 记忆设置。复用 Mnemopi 原有 SQLite 与 bank/project 配置，不让宿主另存一份记忆。默认工作目录相同的群来源也不得被自动混合为所有会话的全局记忆；作用域仅控制默认保存/检索，不增加可信用户之间的访问权限等级。
- **依赖**：步骤 03、06 的会话与来源标识，以及步骤 01 确认的后端作用域入口；后端实际需要的模型、索引或本机依赖按固定版本配置。开关变化在确定的运行边界生效，先处理在途后端任务，再刷新后续注入状态。
- **验证方法**：真实完成自动积累、新会话 recall、支持的查看/编辑/删除及重启恢复；并发会话写入不损坏存储，跨项目/群来源不意外混入记忆。运行中关闭后检查无新 retain/recall/注入，重新开启可找回旧内容；不将先前已进入会话历史的内容消失作为关闭条件。模型或后端失败如实显示状态，不能将启用开关视为记忆已可用。

### 11. 接入可切换的 Skill、上下文与压缩实验

- **预期结果**：三个位置分别提供常规、实验和旁路比较；以 Jev/TypeSafe 及 Laya 适配实现结构化选择/排序，记录质量、延迟、用量和成本。失败或不可用时回退常规策略，未配置实验后端时完整运行普通任务；压缩摘要仍由已有生成模型或选定原文形成。
- **改动区域**：`packages/experiments/` 的策略接口与后端适配；`packages/runtime-omp/` 的按请求 Skill 与上下文/压缩接入；GUI 独立开关、配置及结果摘要。记录候选/片段引用、预算、策略和模型版本、概率含义及最终采用结果；不保存无法追溯来源的评分。
- **依赖**：步骤 05 的实际资源集合、步骤 10 的记忆开关/作用域和步骤 03 的运行边界。步骤 01 的探针须证明可按请求选择 Skill，以及能解除或隔离压缩钩子影响；只在创建会话时注入 Skill 不足以满足要求。优先扩展接口，必要上游改动集中在适配层。
- **验证方法**：同一组中文、混合语言、长上下文任务比较三种模式，包含用户显式 Skill、相似候选、超大候选集、超时和不合法判断。固定规则、最新要求、未完成任务及必要证据不能被筛掉，工具调用/结果结构保持有效。常规/旁路模式不得注册会抑制 speculative compaction 的钩子；若需重建运行进程解除钩子，保存原历史并在可重建边界切换。比较漏选、误选、事实保留、任务结果、延迟与成本，不以分类速度代替任务质量。记忆关闭时实验不能绕过开关重新检索记忆。

### 12. 交付双平台安装包并完成整体验收

- **预期结果**：用户安装 bro 后可配置模型、飞书和系统权限，使用上述完整路径；不需要另行手装匹配的 Bun/OMP。两端后台启停、窗口重开、普通升级后的数据读取与依赖加载均有真实证据；提供启动/诊断说明和已验证的系统/架构范围。
- **改动区域**：`packaging/`、`packages/platform/` 的当前用户后台启动/发现/停止；安装依赖清单、原生模块与 worker 资源、许可证声明、必要平台签名/分发配置；`tests/e2e/` 和交付说明。打包同时包含 bro 所需的固定运行时依赖；项目专用语言/调试工具及外部模型/IM 凭据按实际需求检测和配置。
- **依赖**：步骤 02—11 的必需功能通过，步骤 01 的早期打包路径持续随功能更新。最终 Computer Use 验收需真实 Windows/macOS 交互桌面；无相应环境、凭据或系统权限的项目记录未测，不用模拟通过替代。
- **验证方法**：在没有开发仓库路径和全局 Bun/OMP 依赖的环境，从安装包启动并完成下方整体验证；检查进程启动位置、原生模块/worker/资源、持久数据与正常退出。覆盖长任务期间关窗重开、满足唤醒条件的合盖运行、宿主/会话进程异常恢复及数据版本兼容。汇总实测启动时间、会话恢复和内存占用，确认回收不杀后台工具。任何必需能力缺口仍记为未完成；锁屏探索、Appshots 等暂缓项不充当发布门槛。

| 09 Codex 桌面对话 | 07 + 08 | 接口只读核实可提前；真实收发与接管验证必须等待两项完成 |

安装包必须完成以下连续使用场景，而不只是各模块单测通过：

1. **本地工作**：安装并配置模型，建立项目，修改代码和运行测试，检查结果/diff，对回复添加批注继续任务；长任务期间关窗，再打开同一会话核对结果。
2. **远程交办**：飞书进入 S0，给 S1/S2 分别交办，交办期间继续聊天；目标完成后回到各自原始请求。群聊换成员、引用消息、归档后再次 @，确认上下文和绑定正确。
3. **桌面工作**：飞书要求 bro 操作浏览器或原生应用，再交办真实 Codex 桌面会话；本人接管时自动暂停，手动继续后重新定位并回报对应结果。
4. **恢复与结果交付**：执行期间模拟运行进程中断、已完成结果回复失败、宿主重启；队列与来源关联恢复，已执行但状态不明的操作不自动重做，确定的结果可以独立重发。
5. **记忆与实验**：积累可验证的项目记忆，切换记忆 on/off 和各实验模式，在后续长会话中检查事实、原始记录、任务结果和常规压缩恢复；移除实验配置后普通任务仍完整可用。

测试记录区分自动化协议/状态验证、双平台真实工具运行、真实账号与飞书收发、安装包端到端四类证据。每项记录版本、环境、输入、预期、实际结果和证据位置；模拟平台事件只能验证路由，不能替代官方连接、附件权限或真实群聊。只为有状态、跨进程或副作用风险的行为补必要测试，不为静态排版堆叠重复用例。
